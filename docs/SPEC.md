# 호기야 Spec (1주차: 모의 데이터 범위)

[PRD.md](./PRD.md)의 요구사항을 기능 일곱 개(S01~S07)로 나눠 입력, 행동, 예외, 수용 기준으로 구체화합니다. 모든 데이터는 모의 데이터이고 실제 AI와 DB는 연결하지 않습니다. 용어는 [CONTEXT.md](../CONTEXT.md), 구조 결정은 [docs/adr/](./adr/)를 따릅니다.

## 공통 약속

**데이터 계약.** 모의 데이터는 타입이 있는 객체이며, 3주차에 DB로 바꿔도 같은 타입을 유지합니다.

| Entity | 주요 필드 | 관계 |
|---|---|---|
| 학급 | id, 이름 | 학생 여러 명 |
| 학생 | 합성 id, 번호 | 학급에 속함 |
| 교사 | id, 이름 | 담당 배정 여러 개 |
| 담당 배정 | 교사, 학급, 과목 | 열 수 있는 범위의 기준 |
| 수업 | id, 학급, 과목, 제목, 공개 상태 | 수업 자료 여러 개, 문항 세트 버전 여러 개 |
| 수업 자료 | id, 수업, 제목, 본문 | |
| 문항 세트 | id, 수업, 버전, 상태 | 문항 5개 |
| 문항 | id, 지문, 선택지, 정답, 이유 칸 유무, 개념, 루브릭 | 개념 하나에 연결 |
| 개념 | id, 이름, 확인 활동 안내 | 문항 여러 개가 연결 가능 |
| 시도 | id, 학생, 문항 세트 버전, 시도 키, 답안, 제출 시각 | |
| 답안 | 문항, 선택, 이유 문장 | 시도에 속함 |
| 평가 결과 | 시도, 개념, 이해 수준, 근거 | 시도에서 계산 |
| 다시 설명하기 | 시도, 개념, 글 | 시도의 부속 기록 |

**현재 사용자.** 상단 역할 전환에서 교사 4명 또는 학생 1~20번을 고릅니다. 이후 모든 화면과 조회는 현재 사용자 기준으로 동작합니다.

**화면 표시.** 모의 응답과 검수 전 문항에는 그 사실을 화면에 표시합니다.

---

## S01. 담당 배정과 접근 범위 (FR-01)

**입력**: 현재 사용자, 요청 대상(수업, 자료, 답안)

**행동**
- 교사는 담당 배정에 있는 학급·과목의 수업, 자료, 답안만 열 수 있습니다.
- 학생은 자기 학급의 공개된 수업과 자기 시도만 열 수 있습니다.
- 접근 판단은 한 함수에서 하고, 화면과 데이터 조회가 모두 이 함수를 지납니다.

**예외**
- 범위 밖 요청은 거절하고 "열 수 없는 자료입니다"를 보여 줍니다. 대상이 존재하는지는 알려 주지 않습니다.
- 담당 수업이 없는 교사(국어·영어·수학)는 빈 목록과 안내 문구를 봅니다.

**수용 기준**
- 과학 교사가 같은 학급 수학 수업의 답안 주소를 직접 열면 거절됩니다.
- 학생이 다른 학생의 시도 주소를 직접 열면 거절됩니다.
- 학생이 작성 중인 수업을 직접 열면 거절됩니다.
- 교사 4명 모두 자기 담당 목록만 보입니다.

---

## S02. 수업과 수업 자료 (FR-02)

**입력**: 수업 제목, 수업 자료(제목과 본문 텍스트 여러 개)

**행동**
- 교사는 담당 과목의 수업을 만들고 자료를 추가, 수정, 삭제합니다. 새 수업은 작성 중으로 시작합니다.
- 공개 상태는 작성 중, 공개, 마감입니다. 마감은 다시 공개로 되돌릴 수 있습니다.
- 학생에게는 공개 상태인 수업과, 마감 전에 시도한 수업의 결과만 보입니다.
- 학생의 수업 목록은 과목별로 나뉘고 수업마다 진행 상태(아직 안 함, 선진단 완료, 복습 중)를 보여 줍니다.

**예외**
- 제목이나 본문이 비어 있는 자료는 저장되지 않고 비어 있는 입력 위치를 알려 줍니다.
- 마감한 수업에는 새 시도를 만들 수 없습니다.

**수용 기준**
- 교사가 자료를 등록하고 공개하면 6학년 2반 학생 전원의 수업 목록에 나타납니다.
- 작성 중인 수업은 학생 목록에 나타나지 않습니다.
- 마감한 수업에서 학생이 선진단을 시작하려 하면 막히고, 이전 결과는 계속 볼 수 있습니다.

---

## S03. 문항 세트와 루브릭, 공개 (FR-03)

**입력**: 문항 5개. 문항마다 지문, 선택지, 정답, 이유 칸 유무, 연결 개념, 루브릭(판단 근거 문장). 개념마다 이름과 확인 활동 안내 한 줄.

**행동**
- 교사는 수업에 문항 세트를 만들고 문항을 편집합니다.
- 문항이 정확히 5개이고, 각 문항에 정답, 개념, 루브릭이 있고, "더 알아봐요"가 될 수 있는 모든 개념에 확인 활동 안내가 있을 때만 수업을 공개할 수 있습니다.
- 문항 하나는 개념 하나에만 연결합니다. 개념 하나에는 문항 여러 개를 연결할 수 있습니다.
- 공개된 문항 세트나 루브릭을 고치면 새 버전이 되고, 이전 버전은 보존됩니다. 이미 낸 시도는 제출 당시 버전에 연결된 채로 남습니다(ADR 0001).

**예외**
- 공개 조건이 부족하면 공개 단추를 누를 때 무엇이 부족한지 항목별로 알려 줍니다.
- 정답이 선택지에 없으면 저장되지 않습니다.

**수용 기준**
- 문항이 4개이면 공개가 거절되고 "문항 1개가 더 필요합니다"가 표시됩니다.
- 공개 뒤 문항 지문을 고치면 버전이 2가 되고, 고치기 전 제출한 시도는 버전 1에 연결된 채로 조회됩니다.
- 문항 하나에 개념을 둘 이상 연결하려 하면 막힙니다.
- 기본 모의 데이터는 「전기의 이용」 5문항(검수 전 초안 표시)과 개념 2~3개를 담고 있습니다.

## S04. 선진단 제출 (FR-04)

**입력**: 현재 학생, 수업, 문항별 선택과 이유 문장, 시도 키

**행동**
- 학생은 공개 상태인 수업에서 5문항에 답하고 제출합니다. 선택은 필수이고, 이유 칸이 있는 문항의 이유 문장은 선택 입력입니다.
- 제출할 때마다 시도 키를 만들어 함께 보냅니다. 같은 학생이 같은 시도 키로 다시 요청하면 새 시도를 만들지 않고 기존 시도를 돌려줍니다.
- 같은 학생이 같은 수업을 다시 풀면 새 시도 키로 새 시도가 쌓입니다. 횟수 제한은 없습니다(ADR 0002).
- 제출 직후 결과와 복습 화면(S05)으로 이동합니다.

**예외**
- 선택하지 않은 문항이 있으면 제출하지 않고 첫 미응답 문항으로 이동해 입력 위치를 알려 줍니다.
- 제출 처리가 실패해도 입력한 답은 화면에 남고, 다시 시도할 수 있게 안내합니다.

**수용 기준**
- 한 문항을 비우고 제출하면 막히고, 그 문항이 강조됩니다.
- 같은 시도 키로 두 번 제출해도 시도는 한 번만 기록됩니다.
- 같은 학생이 새로 풀기를 눌러 제출하면 시도가 2개가 되고 참여 횟수가 2가 됩니다.
- 입력 화면에 이름, 전화번호, 이메일을 묻는 칸이 없습니다.

---

## S05. 이해 수준 판정과 복습 (FR-05)

**입력**: 시도(답안, 문항 세트 버전)

**행동**
- 판정 함수가 시도의 선택형 답안과 문항 세트 버전의 정답으로 개념별 맞힌 비율을 구합니다. 이 함수가 이해 수준을 정하는 유일한 곳입니다.

| 개념에 연결된 문항을 맞힌 비율 | 이해 수준 |
|---|---|
| 전부 | 잘 알아요 |
| 절반 이상 | 거의 알아요 |
| 절반 미만 | 더 알아봐요 |

- 평가 결과에는 수준과 근거(어느 문항을 맞히고 틀렸는지)를 함께 저장합니다.
- 복습 화면 왼쪽은 아래 순서입니다.
  1. 개념별 이해 수준 카드와 근거
  2. "더 알아봐요" 개념마다 확인 활동 안내 한 줄
  3. 개념별 다시 설명하기 입력 칸
- 다시 설명하기 글은 시도의 부속 기록으로 저장하고, 이해 수준과 집계에는 영향을 주지 않습니다.
- 이유 문장은 1주차에 판정하지 않고 저장해 교사 화면(S07)에서만 보여 줍니다.

**예외**
- 개념이 모두 "잘 알아요"이면 확인 활동 안내 대신 "모두 잘 알고 있어요"를 보여 줍니다.
- 다시 설명하기 글이 비어 있으면 저장하지 않고 그대로 둡니다. 필수가 아닙니다.

**수용 기준**
- 개념 A에 연결된 문항 2개 중 1개를 맞히면 A가 "거의 알아요"입니다.
- 개념에 연결된 문항 1개를 틀리면 "더 알아봐요"입니다.
- 같은 답안과 같은 버전으로 판정 함수를 여러 번 호출해도 결과가 같습니다.
- 전지·전구의 직렬·병렬을 혼동한 답안의 예시 모의 데이터에서 "더 알아봐요"와 확인 활동 안내가 표시됩니다.
- 다시 설명하기를 저장한 뒤에도 대시보드 집계 값이 바뀌지 않습니다.

## S06. 호기 패널 (FR-06)

**입력**: 학생의 질문, 현재 보고 있는 개념(또는 문항), 해당 수업의 수업 자료

**행동**
- 복습 화면 오른쪽에 호기 패널이 있고, 왼쪽에서 보고 있는 개념이 바뀌면 패널의 문맥도 바뀝니다.
- 응답 함수 하나가 입력을 받아 응답을 만듭니다. 1주차에는 개념마다 미리 쓴 설명을 돌려주고, 설명에는 근거가 된 수업 자료의 제목을 표시합니다.
- 호기에게 전달하는 입력은 현재 개념과 그 수업의 승인된 자료로 제한합니다. 다른 학생의 답안, 다른 과목의 자료, 학생의 이름은 전달하지 않습니다.
- 패널에는 "모의 응답입니다" 표시를 둡니다.

**예외**
- 연결된 자료가 없는 질문에는 "자료의 해당 부분을 다시 확인하거나 선생님께 물어보세요"를 안내합니다.
- 수업과 무관한 질문에는 한 문장으로 돌려보내고 현재 개념으로 다시 안내합니다.
- 응답 함수가 실패해도 왼쪽의 결과와 제출한 답안은 그대로 조회됩니다.

**수용 기준**
- 전구 직렬·병렬 개념에서 질문하면 그 개념의 설명과 자료 제목이 함께 나옵니다.
- 근거가 없는 질문을 하면 추측하지 않고 확인 안내가 나옵니다.
- 응답 함수를 일부러 실패시켜도 결과 화면이 사라지지 않고 제출 횟수가 늘지 않습니다.
- 응답 함수가 받은 입력에 학생 이름과 다른 과목 자료가 들어 있지 않습니다.

## S07. 교사 대시보드 (FR-08)

**입력**: 현재 교사, 수업(담당 배정 범위), 합성 시도 데이터

**행동**
- 교사는 담당 과목 수업별로 아래를 봅니다.
  - **참여 횟수**: 모든 시도의 합
  - **수준별 분포**: 학생마다 최근 시도 기준으로, 개념별 "더 알아봐요, 거의 알아요, 잘 알아요"의 인원
  - **재지도 대상 개념**: "더 알아봐요" 인원이 많은 순서의 개념 목록
- 학급 전체 화면에는 분포와 개념 목록만 보이고, 개인 답안은 개념이나 문항을 눌러 내려가야 엽니다.
- 내려가면 학생 번호, 선택, 이유 문장, 판단 근거를 볼 수 있습니다. 학생 이름은 없습니다.
- 대시보드가 보여 주는 문항 세트 버전을 표시합니다(첫 버전은 최신 버전 기준).
- 합성 시도 데이터는 기대 집계를 함께 둬서 화면의 값과 비교할 수 있게 합니다.

**예외**
- 시도가 없는 수업에는 "아직 선진단을 한 학생이 없어요"를 보여 줍니다.
- 담당이 아닌 수업의 대시보드는 열리지 않습니다(S01).

**수용 기준**
- 합성 데이터로 계산한 참여 횟수, 수준별 분포, 재지도 대상 개념이 기대 집계와 일치합니다.
- 한 학생이 두 번 시도했다면 분포에는 최근 시도만 반영되고 참여 횟수에는 두 번이 모두 반영됩니다.
- 학생이 새 시도를 제출하면 대시보드의 분포가 즉시 바뀝니다.
- 학급 전체 화면에서 개인 이름이나 번호가 보이지 않습니다.

## 후속 Spec

| 요구사항 | 시점 | 비고 |
|---|---|---|
| FR-07 승인된 자료 조회(MCP) | 2주차 | 허용 목록, 읽기 전용, 자료 제목 표시, 연결 끊김 시 안내 |
| FR-06 실연결 | 2주차 | S06의 응답 함수 내부만 Claude API로 교체 |
| FR-09 정보 최소 수집과 삭제 | 3주차 | 이유 문장과 다시 설명하기 입력에 대한 개인정보 검사 포함 |
| FR-01·08 실연결 | 3주차 | 접근 판단 함수의 규칙을 RLS로 옮김 |
| FR-10 평가와 개선 비교 | 4~5주차 | 교사 채점 사례 10~20개 |

## 구현 순서 제안

1. 데이터 계약과 모의 데이터, 현재 사용자 전환(공통)
2. S01 접근 판단 함수
3. S03 문항 세트와 공개(교사 쪽 입력이 이후 화면의 재료가 됨)
4. S02 수업과 자료
5. S04 선진단 제출
6. S05 판정 함수와 복습

8. S07 대시보드
